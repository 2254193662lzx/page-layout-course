## 快速开始

```bash
# 1. 构建静态站点（输出到 docs/）
node build.mjs

# 2. 本地预览（任选一种，需通过 HTTP 访问，因为用了 ES Modules）
python -m http.server 8080 --directory docs
#   然后打开 http://127.0.0.1:8080/
```

构建时只想处理部分章节（写作时迭代更快）：

```bash
PLC_CHAPTERS=1,2 node build.mjs     # 只构建第 1、2 章
```

## 设计说明

### 双语一致性的机制保证

内容以 `{ zh, en }` 结构化数据书写，构建器（`build.mjs` 的 `pair()`）**成对输出**双语节点：

```html
<p data-lang="zh-CN">…</p>
<p data-lang="en-US" hidden>…</p>
```

- 界面固定文案用 `data-i18n="key"`（`lang.js` 运行时替换）
- 语言状态存 `localStorage('plc-locale')`，支持 `?lang=en` 直达
- 切换语言时演示会整体重渲染，所以演示内部文案也同步切换
- 即使两种语言文本相同也成对输出，使"每个 `data-lang="zh-CN"` 节点都有配对的 `en-US` 节点"成为**可被脚本审计的不变量**

### 演示的"数字来自浏览器"

18 个演示中的评分、误差、溢出、对比度都不是写死的常量，而是当场从
`getComputedStyle()` / `getBoundingClientRect()` / `elementFromPoint()` 读回的真实结果：

- 对齐误差 = 元素左边缘到最近 8pt 刻度的距离（容差 1.25px，用于排除亚像素布局与 1px 边框的整体偏移）
- 层次评分 = 字号比 35% + 组间组内比 30% + 按钮块面对比度 15% + 对齐漂移 20%
- 破坏性测试与可访问性报告：对 v1/v2 两套写法分别施加压力，统计通过项数
