第 1 章 布局是信息设计

Chapter 1 Layout Is Information Design

布局不是把盒子摆好看，而是用空间、尺寸和顺序，替读者把信息排好优先级。这一章先建立判断标准，再动手。

Layout is not about arranging boxes prettily; it is about using space, size and order to set priorities for the reader. This chapter builds the criteria before we touch any CSS.

1.1 布局决定「能不能被读懂」

1.1 Layout decides whether the page can be read

人眼不会逐字阅读，而是先抓「块」和「差异」。布局的第一职责，是让眼睛知道先看什么。

The eye does not read character by character; it grabs chunks and differences first. The first job of layout is to tell the eye what to look at first.

先做一个观察实验：把 CourseHub 首页截图高斯模糊到看不清文字，你还能分辨出「这是导航、这是标题、这是正文、这里可以点击」吗？如果不能，说明布局的信息职责没有完成——读者之所以能找到内容，靠的是你在页面上制造出来的差异，而不是文字本身。

Try a quick experiment: blur a screenshot of the CourseHub landing page until the text is illegible. Can you still tell what is navigation, what is a heading, what is body copy, and where you can click? If not, the layout has failed its informational job — readers find things because of the differences you create on the page, not because of the words themselves.

一、人眼先看到「分组」，而不是「元素」

1. The eye sees groups before it sees elements

1912 年起，格式塔心理学家提出一组知觉组织原则，解释了人脑如何把零散视觉信号自动组织成结构。做布局时最常用的四条：

From 1912 on, Gestalt psychologists described how the brain automatically organises scattered visual signals into structure. Four of their principles matter most for layout:

原则含义布局里的用法
接近性 Proximity距离近的元素被看作一组用间距表达归属：卡片内 8–12px，卡片间 24–32px，组间距必须大于组内间距
相似性 Similarity外观相似的元素被看作同类同类元素共享一套字号/颜色/圆角，靠 token 而不是靠手写
共同区域 Common region同一容器内的元素被看作一组卡片、区块背景、分隔线，是比间距更强的分组信号
连续性与闭合 Continuity / Closure对齐的边线会被眼睛自动连成一条线左对齐一条竖线，能让整页"看起来整齐"，即使元素内容各异
PrincipleMeaningUse in layout
ProximityElements that are close are read as one groupEncode grouping with spacing: 8–12px inside a card, 24–32px between cards. Between-group spacing must exceed within-group spacing
SimilarityElements that look alike are read as the same kindSame-kind elements share one type scale, colour and radius — via tokens, not by hand
Common regionElements inside one container are read as a groupCards, section backgrounds and dividers group more strongly than spacing alone

🧠 Theory: Layout is essentially encoding data structure visually: proximity encodes membership, similarity encodes category, common region encodes module boundaries. When your spacings vary randomly or same-kind elements differ, you are broadcasting wrong syntax — and the reader gets tired. That is the neurological source of "it just feels off".Wertheimer 1923, "Untersuchungen zur Lehre von der Gestalt"; Arnell & Larson 2009 on proximity effects on attention

二、视觉层次：制造"阅读顺序"

2. Visual hierarchy: manufacturing a reading order

视觉层次（visual hierarchy）指的是：在不改变文案的前提下，让读者按你希望的顺序接收信息。它靠三个变量制造差异——尺寸（谁更大）、对比（谁更重/更亮）、空间（谁被孤立出来）。1.2 节会把三者变成可调的滑杆。

Visual hierarchy means getting the reader to receive information in the order you intend, without changing a word of copy. It is created by three variables: size (what is bigger), contrast (what is heavier or brighter) and space (what is isolated). Section 1.2 turns these into sliders you can drag.

关于"顺序"，有两个被广泛引用的观察：F 型阅读模式（以文字为主的页面，视线先横扫顶部、再横扫中部、最后竖向扫左侧）和 Z 型阅读模式（视觉型落地页，视线走左上 → 右上 → 左下 → 右下）。它们不是铁律，但给出了一个实用推论：页面左上是最贵的空间，右下是最适合放行动按钮的位置。

Two widely cited observations about order: the F pattern (text-heavy pages: scan the top, scan a second line, then scan down the left edge) and the Z pattern (visual landing pages: top-left → top-right → bottom-left → bottom-right). They are not laws, but they yield a useful corollary: the top-left is the most expensive real estate, and the bottom-right is the natural home for the action button.

课堂要点：信息层次的检查方法只有一句话——眯眼看（或者把页面缩小到 25%）。如果眯眼之后看不出「哪个是第一、哪个是第二」，说明层次没做出来，而不是用户不够专注。

Classroom takeaway: there is a one-sentence test for hierarchy — squint (or zoom the page out to 25%). If you cannot tell "what is first and what is second" while squinting, the hierarchy is missing; the user is not the problem.

🧩 案例诊断：问题 ① 层次缺失CourseHub v1 的 HTML 是"正确的"：有 <h1>、<p>、<button>，语义没问题。但 CSS 里写了一条 body { font-size: 16px; } 之后，浏览器默认的标题尺寸被重置了，所有文字都是 16px。结果：用户读完三屏才意识到"往下有个报名按钮"。语义正确 ≠ 视觉可读，这是初学者最常见的一类"看不出错在哪"的问题。
🧩 Case diagnosis: defect ① no hierarchyThe v1 markup is "correct": it has <h1>, <p> and <button> with proper semantics. But one line of CSS — body { font-size: 16px; } — resets the browser’s default heading sizes, so everything renders at 16px. Users had to read three screens before realising an Enroll button existed. Semantically correct ≠ visually readable, and this is the classic beginner bug that "looks like nothing is wrong".
/* 病态：所有元素同尺寸，没有差异可言 */
body { font-size: 16px; }
h1, h2, h3, p, button { font-size: 1em; }
/* The defect: every element is the same size, so there is no difference */
body { font-size: 16px; }
h1, h2, h3, p, button { font-size: 1em; }

关键代码 ① 用一条横向尺度重建层次

Key code ① Rebuild hierarchy with one type scale

层次来自"比例"，不是来自"绝对值"。先把尺度定义成变量，页面里只允许从尺度里取值。

Hierarchy comes from ratios, not absolute values. Define the scale as variables first, then only ever pick values from that scale.

/* ⭐ 关键点 ①：模数尺度 = 一个基准 × 逐级倍率，层次才有"家族感" */
:root {
  --step-0: 1rem;                              /* 正文基准 16px */
  --ratio: 1.25;                               /* 倍率：小屏用 1.2，大屏可到 1.5 */
  --step-1: calc(var(--step-0) * var(--ratio));       /* 20px  卡片标题 */
  --step-2: calc(var(--step-1) * var(--ratio));       /* 25px  小节标题 */
  --step-3: calc(var(--step-2) * var(--ratio));       /* 31px  H2 */
  --step-4: calc(var(--step-3) * var(--ratio));       /* 39px  H1 */
  --step--1: calc(var(--step-0) / var(--ratio));      /* 12.8px 辅助文字 */
}

/* ⭐ 关键点 ②：只给"需要被区分"的元素分配级别，其余继承 */
h1 { font-size: var(--step-4); line-height: 1.1; }
h2 { font-size: var(--step-3); line-height: 1.2; }
.card h3 { font-size: var(--step-1); line-height: 1.3; }
small, .meta { font-size: var(--step--1); }
/* ⭐ Key point ①: a modular scale = one base × one ratio, so levels look related */
:root {
  --step-0: 1rem;                              /* body base 16px */
  --ratio: 1.25;                               /* ratio: 1.2 on small screens, up to 1.5 on large */
  --step-1: calc(var(--step-0) * var(--ratio));       /* 20px  card title */
  --step-2: calc(var(--step-1) * var(--ratio));       /* 25px  section title */
  --step-3: calc(var(--step-2) * var(--ratio));       /* 31px  H2 */
  --step-4: calc(var(--step-3) * var(--ratio));       /* 39px  H1 */
  --step--1: calc(var(--step-0) / var(--ratio));      /* 12.8px helper text */
}

/* ⭐ Key point ②: only assign levels to what must be distinguished; everything else inherits */
h1 { font-size: var(--step-4); line-height: 1.1; }
h2 { font-size: var(--step-3); line-height: 1.2; }
.card h3 { font-size: var(--step-1); line-height: 1.3; }
small, .meta { font-size: var(--step--1); }

关键点解释：为什么是"乘一个倍率"而不是"每个级别单独拍脑袋定尺寸"？因为人眼判断层次靠的是相邻级别的比值。等比数列让每次跳跃的"视觉力度"一致，页面读起来像一首有节拍的曲子；如果 39 / 25 / 16 这种比例忽大忽小，读者会觉得"有的标题太夸张，有的又不够"。坑：倍率不要低于 1.1，否则两级标题看起来几乎一样；也不要超过 1.6，否则大标题会吃掉整个首屏。

Key point: Why multiply by one ratio instead of hand-picking each size? Because the eye judges hierarchy by the ratio between adjacent levels. A geometric progression gives every jump an equal visual force, so the page reads with a beat. When ratios swing (39 / 25 / 16 …), readers feel that "some headings shout and others murmur". Pitfall: keep the ratio above 1.1, or two levels look identical; keep it below 1.6, or the largest heading eats the whole first screen.

关键代码 ② 一行布局把按钮"推"出来

Key code ② One layout line that pushes the button forward

层次不只靠字号，还靠空间。把行动按钮从正文流中"孤立"出来，是成本最低的层次手段。

Hierarchy is not only type size; it is also space. Isolating the call to action from the text flow is the cheapest hierarchy tool there is.

.hero {
  /* ⭐ 关键点 ③：用"组间间距 > 组内间距"实现分层，读者会自动分块 */
  display: flex;               /* 主轴方向堆叠 */
  flex-direction: column;
  gap: var(--space-2);         /* 组内 8px：标题与副标题属于同一块 */
  padding-block-end: var(--space-6);   /* 组间 32px：与下面的按钮明确分开 */
}
.hero .cta {
  margin-block-start: var(--space-4);  /* ⭐ 关键点 ④：给按钮额外的上方留白 = 视觉升权 */
  align-self: flex-start;              /* 按钮不要被拉满整行，宽度即"重要性声明" */
  font-size: var(--step-0);
  padding: var(--space-3) var(--space-5);
}
.hero {
  /* ⭐ Key point ③: group separation = "between-group spacing > within-group spacing" */
  display: flex;               /* stack along the main axis */
  flex-direction: column;
  gap: var(--space-2);         /* within group: 8px — title and subtitle belong together */
  padding-block-end: var(--space-6);   /* between groups: 32px — clearly separated from what follows */
}
.hero .cta {
  margin-block-start: var(--space-4);  /* ⭐ Key point ④: extra space above = visual promotion */
  align-self: flex-start;              /* do not stretch full width; width itself signals importance */
  font-size: var(--step-0);
  padding: var(--space-3) var(--space-5);
}

关键点解释：gap 与 margin 在这里分工不同：gap 表达组内关系（属于一起的，间距小且均匀），margin 表达组间关系（需要被分开的，间距大）。这就是把格式塔的接近性翻译成 CSS 的方式。另外注意用的是逻辑属性 padding-block-end / margin-block-start：它们会随书写方向自动映射到上下/左右，对多语言（含从右到左语言）更友好。坑：如果这里用 margin-bottom 叠 margin-top，会诱发外边距折叠（见 2.2），间距值不再是你要的那个数。

Key point: gap and margin do different jobs here: gap expresses within-group relations (small, uniform), margin expresses between-group relations (large). That is Gestalt proximity translated into CSS. Note the logical properties padding-block-end / margin-block-start: they map to top/bottom or left/right automatically according to writing mode, which is friendlier for multilingual pages (including right-to-left). Pitfall: mixing margin-bottom and margin-top invites margin collapsing (see 2.2), and the resulting spacing is no longer the number you wrote.

1.2 视觉层次的四个杠杆

1.2 The four levers of visual hierarchy

尺寸、间距、对比、对齐：把"设计感"拆成四个可以分别调节、并且可以量化的旋钮。

Size, space, contrast, alignment: splitting "design sense" into four knobs you can tune separately — and measure.

设计师常被要求"做得好看一点"，但"好看"没法执行。把这句话翻译成可执行的四条，来自 Robin Williams 总结的 CRAP 原则：Contrast（对比）、Repetition（重复）、Alignment（对齐）、Proximity（接近）。其中对比、对齐、接近直接由布局承担；重复则由设计 token 承担。

Designers are often told to "make it prettier", which is not actionable. Robin Williams’ CRAP principles translate that request into four executable rules: Contrast, Repetition, Alignment, Proximity. Contrast, alignment and proximity are the layout’s job; repetition is the job of design tokens.

杠杆一：尺寸（Size）

Lever 1: size

尺寸是最强的层次信号——在低分辨率、模糊、远距离、色盲等不利条件下，大小差异仍然可辨。因此页面最重要的东西应该最大。反过来说，如果一个次要元素做得和主元素一样大，读者就必须靠阅读内容才能判断主次，成本立刻上升。

Size is the strongest hierarchy signal: it survives blur, distance, low resolution and colour-blindness. So the most important thing on the page should be the biggest. Conversely, if a secondary element is as big as the primary one, the reader must read the content to work out the priority — an immediate cost.

杠杆二：间距（Space）

Lever 2: space

间距是最容易被忽略、却最影响"高级感"的杠杆。它有三个作用：分组（接近性）、呼吸（降低认知负荷）、强调（被空白包围的元素自动升权）。注意最后一条：留白不是"没用的空间"，而是主动的强调手段。给按钮上方加 32px 留白，比给它加粗更有效。

Space is the most overlooked lever and the one that most affects the feeling of quality. It does three things: grouping (proximity), breathing (lower cognitive load) and emphasis (whatever is surrounded by whitespace gains rank). Note the last one: whitespace is not wasted space, it is an active emphasis tool. Adding 32px above a button works better than making it bold.

杠杆三：对比（Contrast）

Lever 3: contrast

对比包括字重、颜色明度、底色块、边框。它比尺寸更"细腻"，适合区分同一级别内的差异（比如正文 vs 辅助说明）。但对比有个硬约束：可访问性。正文文字与其背景的对比度至少要 4.5:1（WCAG 1.4.3 AA），大字号至少 3:1。这一条会在 6.2 节用工具量化检查。

Contrast covers weight, lightness, background blocks and borders. It is subtler than size and is best for distinguishing items within one level (body text vs helper text). But contrast has a hard constraint: accessibility. Body text needs at least 4.5:1 against its background (WCAG 1.4.3 AA) and large text at least 3:1. Section 6.2 measures this with a tool.

杠杆四：对齐（Alignment）

Lever 4: alignment

对齐几乎不"抢眼"，但它决定了页面是否显得专业。原理是格式塔的连续性：当多个元素共享一条边线，眼睛会把它们连成一条隐含的线，产生秩序感。这就是为什么一个界面里应该只有少数几条对齐线（左对齐线、网格线），而且每条线都要有理由。

Alignment rarely draws attention, yet it decides whether a page looks professional. The mechanism is Gestalt continuity: when several elements share an edge, the eye connects them into an implied line, producing order. That is why an interface should have only a few alignment lines (a left edge, a grid), each with a reason to exist.

四个杠杆的优先级：尺寸 > 间距 > 对比 > 对齐。先用尺寸建立大结构，再用间距分组，再用对比做细微区分，最后用对齐收拢全局。反过来做（先抠颜色）就是典型的"细节精致但结构混乱"。

Priority order: size > space > contrast > alignment. Use size for the big structure, space for grouping, contrast for fine distinctions, and alignment to tie the whole page together at the end. Doing it in reverse (fiddling with colours first) is the classic "polished details, chaotic structure" outcome.

🧠 理论支点：为什么"对齐"能带来秩序感？因为视觉系统会把共线元素绑定成一个知觉单元，减少需要单独处理的对象数量（认知心理学里的"组块化 chunking"）。页面上的独立对象越少，处理越快、越像"一个整体"。这也是网格系统（第 4 章）的理论起点。Robin Williams《The Non-Designer’s Design Book》；Miller 1956 关于组块化的经典论文
🧠 Theory: Why does alignment create order? Because the visual system binds collinear elements into a single perceptual unit, reducing the number of objects it must process separately (the chunking effect in cognitive psychology). Fewer independent objects means faster processing and a stronger sense of one whole. This is also where grid systems (Chapter 4) begin.Robin Williams, The Non-Designer’s Design Book; Miller 1956 on chunking
🧩 案例诊断：把四个杠杆一个一个装回去CourseHub v1 的卡片区：标题 16px、正文 16px、标签 16px，卡片内部 padding 21px，卡片之间 margin 13px，标签用下划线表示可点。四个杠杆全部失效：没有尺寸差；组间距（13）竟然小于组内边距（21），两张卡片在视觉上粘成一整块，读者分不清哪行文字属于哪张卡；对比只剩一条下划线；左对齐线有 2 条。1.2 的演示会把这四个杠杆做成滑杆，让你亲眼看到"层次评分"如何从 9 分涨到 100 分。
🧩 Case diagnosis: reinstalling the four levers one by oneThe card area of v1: title 16px, body 16px, tags 16px, card padding 21px, gap between cards 13px, tags underlined to signal clickability. All four levers fail: no size difference; the gap between cards (13) is smaller than the padding inside them (21), so two cards visually merge into one block and readers cannot tell which text belongs to which card; contrast is limited to an underline; there are two competing left edges. 关键代码 ① 用 clamp() 让尺寸杠杆自己也"响应式"

Key code ① Make the size lever itself responsive with clamp()

固定字号会让层次在小屏上失效（39px 标题在 320px 屏幕上很凶），clamp() 让"倍率"随视口平滑变化，而不是靠断点硬切。

Fixed sizes break hierarchy on small screens (a 39px heading is aggressive at 320px). clamp() lets the ratio change smoothly with the viewport instead of snapping at breakpoints.

/* ⭐ 关键点 ①：clamp(最小值, 弹性值, 最大值)
   中间那项用 vw，两侧兜住"太小看不清 / 太大挤爆" */
h1 {
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 2.75rem);
}
/* 读法：视口 320px → 约 28px 底线；视口 1440px → 约 44px 上限 */

/* ⭐ 关键点 ②：把比例的"下限"锁住，保证层次永不消失 */
:root {
  --step-4: clamp(1.75rem, 1.1rem + 2.4vw, 2.75rem);
  --step-3: clamp(1.375rem, 1rem + 1.2vw, 2rem);
  --step-1: 1.25rem;             /* 卡片标题不参与缩放，保证小屏也压得住正文 */
}
/* ⭐ Key point ①: clamp(min, preferred, max)
   the middle value uses vw; the outer bounds stop "too small" / "too big" */
h1 {
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 2.75rem);
}
/* Reads as: at 320px viewport → about 28px floor; at 1440px → about 44px ceiling */

/* ⭐ Key point ②: lock the lower bound of each step so hierarchy never collapses */
:root {
  --step-4: clamp(1.75rem, 1.1rem + 2.4vw, 2.75rem);
  --step-3: clamp(1.375rem, 1rem + 1.2vw, 2rem);
  --step-1: 1.25rem;             /* card titles do not scale, so they still beat body text on phones */
}

关键点解释：很多人直接用 font-size: 2.5vw，这在窄视口会小到读不了，在宽视口又大到失控。clamp() 的价值在于两侧兜底，让中间那段可以自由插值。另一个细节：文字缩放必须与用户的浏览器缩放共存（WCAG 1.4.4），所以用 rem 而不是 px 表达 clamp 的上下限——用户放大字号时，rem 会跟着长大，px 不会。

Key point: Many people write font-size: 2.5vw, which becomes unreadably small on narrow viewports and absurdly large on wide ones. The value of clamp() is bounding both ends so the middle can interpolate freely. One more detail: text scaling must coexist with browser zoom (WCAG 1.4.4), so express the clamp bounds in rem, not px — rem grows when the user increases the default font size, px does not.

关键代码 ② 间距的三级语义：用命名表达关系

Key code ② Three spacing levels: naming the relationship

gap/margin 的取值不该由"这里看起来空多少"决定，而应由"这两个元素是什么关系"决定。

gap/margin values should not be chosen by "how empty does it look here" but by "what is the relationship between these two elements".

/* ⭐ 关键点 ③：三个语义层级，组内 < 组间 < 区块间，永远保持 1 : 2 : 4 的量级关系 */
:root {
  --gap-inline: 0.5rem;   /*  8px  同一句话里的元素（图标 + 文字） */
  --gap-stack:  1rem;     /* 16px  同一块内的多行（标题 + 正文）   */
  --gap-group:  2rem;     /* 32px  不同块之间（卡片 → 卡片）        */
  --gap-block:  4rem;     /* 64px  不同区块之间（章节 → 章节）      */
}

.card {
  padding: var(--gap-stack);
  /* ⭐ 关键点 ④：用 flex + gap 而不是给子元素加 margin，
     这样子元素无需知道自己在第几个，也不会产生外边距折叠 */
  display: flex;
  flex-direction: column;
  gap: var(--gap-inline);
}
.card + .card { margin-block-start: var(--gap-group); }
/* ⭐ Key point ③: three semantic levels — within < between < between sections, always 1 : 2 : 4 */
:root {
  --gap-inline: 0.5rem;   /*  8px  elements inside one phrase (icon + label) */
  --gap-stack:  1rem;     /* 16px  lines inside one block (title + body)   */
  --gap-group:  2rem;     /* 32px  between blocks (card → card)            */
  --gap-block:  4rem;     /* 64px  between sections (section → section)    */
}

.card {
  padding: var(--gap-stack);
  /* ⭐ Key point ④: prefer flex + gap over margins on children —
     children need not know their index, and no margin collapsing occurs */
  display: flex;
  flex-direction: column;
  gap: var(--gap-inline);
}
.card + .card { margin-block-start: var(--gap-group); }

关键点解释：把间距命名成关系（inline / stack / group / block）而不是命名成尺寸（sm / md / lg），是从"调样式"升级到"做系统"的关键一步。因为当你写 gap: var(--gap-group) 时，代码里明确记录了"这两个东西不属于一组"这个意图；而 gap: 32px 只记录了数字，半年后没人知道能不能改。

Key point: Naming spacing by relationship (inline / stack / group / block) instead of by size (sm / md / lg) is what upgrades you from styling to building a system. Writing gap: var(--gap-group) records the intent "these two do not belong together"; gap: 32px records only a number, and six months later nobody knows whether it is safe to change.

1.3 用系统而不是手感：8pt 网格与纵向节奏

1.3 Systems, not vibes: the 8pt grid and vertical rhythm

为什么专业界面里的间距总是 4 的倍数？为什么"对不齐"是一种可以被测量的误差？

Why are spacings in professional interfaces always multiples of 4? And why is misalignment a measurable error?

如果每个间距都靠手感定，团队里 5 个人会得到 5 套数值，页面必然"看着不齐"。解决办法不是"更用心"，而是把自由度砍掉：只允许从一套固定的间距序列里取值。这就是 spacing scale（间距尺度），最常见的实现是 8pt 网格。

If every gap is chosen by feel, five people on a team produce five value sets and the page inevitably looks misaligned. The fix is not "more care" but removing degrees of freedom: only values from one fixed sequence are allowed. That sequence is the spacing scale, most commonly implemented as an 8pt grid.

为什么是 8（和 4）？

Why 8 (and 4)?

  • 可整除性好：8 能被 2、4 整除，在 1x / 1.5x / 2x / 3x 各种像素密度下都能落在物理像素上，不会出现半像素导致的模糊。
  • 与常见字号/行高天然对齐：16px 正文、24px 行高的组合正好是 8 的倍数，纵向节奏容易对齐。
  • 相邻级别的视觉差异足够明显：8 → 16 → 24 → 32 每一级都能被眼睛分辨，而 5 → 10 → 15 变化太碎，看起来像"没对齐"。
  • 4pt 是补充：图标与文字之间这类"微间距"用 4 的奇数倍（4、12、20），8 不够用。
  • Divisibility: 8 divides by 2 and 4, so it lands on physical pixels at 1x / 1.5x / 2x / 3x densities without half-pixel blur.
  • Aligns with common type and line heights: 16px body text with 24px line height are both multiples of 8, so vertical rhythm lines up naturally.
  • Adjacent steps are clearly distinguishable: 8 → 16 → 24 → 32 are each visible to the eye, whereas 5 → 10 → 15 are too granular and read as "not aligned".
  • 4pt is the escape hatch: micro-spacing such as icon-to-label needs odd multiples of 4 (4, 12, 20), where 8 is too coarse.
🧠 理论支点：这套思路是排版学里 baseline grid（基线网格）的现代版本。传统印刷把正文行位置固定在一条条基线上，标题、图片、图注都必须"落在线上"，于是整本书产生统一的节奏。网页里行高不固定、元素高度不一，所以现代做法是用统一的间距步长代替基线，把"节奏"从行迁移到块。Josef Müller-Brockmann《Grid Systems in Graphic Design》；Material Design / Atlassian Design System 的 8pt 网格规范
🧠 Theory: This is the modern descendant of the baseline grid in typography. Print fixed body lines onto a baseline so headings, images and captions all "land on the line", giving a book one rhythm. On the web line heights vary and elements differ in height, so the modern approach replaces the baseline with a uniform spacing step, moving rhythm from lines to blocks.Josef Müller-Brockmann, Grid Systems in Graphic Design; the 8pt grid specs in Material Design and the Atlassian Design System

纵向节奏（vertical rhythm）

Vertical rhythm

纵向节奏指：页面从上到下，各行/各块的垂直位置呈现出可预测的重复关系。做法是让行高本身也是步长的整数倍：正文 font-size: 16px; line-height: 24px（3 × 8），卡片间距 32px（4 × 8），区块间距 64px（8 × 8）。这样即使元素高度不同，它们的边界也总落在同一批"刻度"上。

Vertical rhythm means the vertical positions of lines and blocks repeat in a predictable way from top to bottom. Achieve it by making line heights multiples of the step too: body text font-size: 16px; line-height: 24px (3 × 8), card gaps 32px (4 × 8), section gaps 64px (8 × 8). Then even elements of different heights always end on the same set of ticks.

可测量的"对齐误差"：在 1.3 的演示里，每个元素的边界都会与最近的 8pt 刻度比较，差值就是它的对齐误差。误差为 0 的元素边界会连成水平线；误差不为 0 的元素会成为"孤立的一条边"。一眼看去"有点乱"的页面，往往就是有 3–5 个元素带着 3–5px 的误差。

Measurable alignment error: in the 1.3 demo, every element edge is compared with the nearest 8pt tick and the difference is its alignment error. Edges with zero error join a horizontal line; edges with non-zero error stand alone. A page that "looks a bit messy" usually has three to five elements carrying three to five pixels of error.

🧩 案例诊断：问题 ② 间距无系统CourseHub v1 的间距来自设计师"看着调"：卡片内边距 21px、卡片间距 13px、区块间距 37px。这三个数互不成倍数，于是出现两个后果：①分组信号反了——卡片之间的留白（13px）比卡片自己的内边距（21px）还小，两张卡片在视觉上粘成一整块；②边缘全部脱离刻度——21、13、37 除以 8 的余数分别是 5、5、5，于是每个元素的边缘都落在 8pt 刻度之外 5px 处。换成 24 / 32 / 64 之后，组间:组内 从 1.44 : 1 变成 4 : 1，最大对齐误差归零，页面立刻"立"住了，而且一个字都不用改。
🧩 Case diagnosis: defect ② arbitrary spacingSpacings in v1 were tuned by eye: 21px inside a card, 13px between cards, 37px between sections. None is a multiple of the others, with two consequences. (1) The grouping signal is inverted — the gap between cards (13px) is smaller than the padding inside them (21px), so two cards visually fuse into one block. (2) Every edge falls off the scale — 21, 13 and 37 all leave a remainder of 5 when divided by 8, so every element sits 5px away from the nearest 8pt tick. Switching to 24 / 32 / 64 moves between:within from 1.44:1 to 4:1 and drives the maximum alignment error to zero — the page stands up without changing a single word.

关键代码 ① 8pt 间距尺度：写成量表，而不是散落的数字

Key code ① The 8pt scale: one table, not scattered numbers

把允许使用的间距值穷举成 token，团队里任何人都不再需要"猜"。

Enumerate the allowed spacing values as tokens so nobody on the team has to guess.

/* ⭐ 关键点 ①：整张表就是"允许使用的全部间距"，
   代码审查时任何不在表里的数字都属于违规 */
:root {
  --space-0: 0;
  --space-1: 0.25rem;  /*  4px  micro：图标与文字 */
  --space-2: 0.5rem;   /*  8px  组内 */
  --space-3: 0.75rem;  /* 12px  组内（偏大的组） */
  --space-4: 1rem;     /* 16px  块内 */
  --space-5: 1.5rem;   /* 24px  块内（宽松） */
  --space-6: 2rem;     /* 32px  块间 */
  --space-8: 4rem;     /* 64px  区块间 */
}

/* ⭐ 关键点 ②：用"尺子"约束自己 —— 布局容器只认这几个值 */
.section { padding-block: var(--space-8); }
.card-grid { gap: var(--space-6); }
.card { padding: var(--space-5); }
.card > * + * { margin-block-start: var(--space-2); }
/* ⭐ Key point ①: this table IS the complete set of allowed spacings.
   In code review, any number not in the table is a violation. */
:root {
  --space-0: 0;
  --space-1: 0.25rem;  /*  4px  micro: icon ↔ label */
  --space-2: 0.5rem;   /*  8px  within a group */
  --space-3: 0.75rem;  /* 12px  within a larger group */
  --space-4: 1rem;     /* 16px  within a block */
  --space-5: 1.5rem;   /* 24px  within a loose block */
  --space-6: 2rem;     /* 32px  between blocks */
  --space-8: 4rem;     /* 64px  between sections */
}

/* ⭐ Key point ②: constrain yourself to the ruler — containers only use these values */
.section { padding-block: var(--space-8); }
.card-grid { gap: var(--space-6); }
.card { padding: var(--space-5); }
.card > * + * { margin-block-start: var(--space-2); }

关键点解释：注意 token 名里的数字是尺度的索引（1、2、3…）而不是像素值，这样以后想整体放大间距（比如做"宽松版"主题），只改表里的 px，所有引用点自动跟随。坑：不要让 token 名带具体用途（如 --space-card），一旦某个间距被两个地方用在不同语义上，命名就会互相拉扯；语义交给使用处（gap: var(--space-6) 已经说明了它是"块间"）。

Key point: Note the numbers in the token names are scale indices (1, 2, 3…) rather than pixel values, so a global "roomier theme" only needs the px column changed and every reference follows. Pitfall: do not name tokens after their use (e.g. --space-card) — once one spacing serves two different meanings, the name fights itself. Meaning belongs at the point of use, where gap: var(--space-6) already says "between blocks".

关键代码 ② 纵向节奏：给内容装一条隐形基线

Key code ② Vertical rhythm: an invisible baseline for content

让行高与间距共享同一套刻度，页面从上到下就会落在一批固定的水平线上。

Make line heights and spacings share one set of ticks, and the whole page lands on a fixed set of horizontal lines.

:root {
  --leading: 1.5;                 /* 行高倍率 */
  --rhythm: calc(1rem * var(--leading));   /* 24px = 3 × 8，节奏单位 */
}

body {
  font-size: 1rem;                /* 16px */
  line-height: var(--rhythm);     /* ⭐ 关键点 ③：行高 = 节奏单位，正文每行都落在刻度上 */
}

h1 {
  /* ⭐ 关键点 ④：标题行高也得是步长整数倍，否则下一段就会错位 */
  font-size: var(--step-4);                  /* 约 44px */
  line-height: calc(var(--rhythm) * 2);      /* 48px = 6 × 8 */
  margin-block: 0 calc(var(--rhythm) * 1);   /* 上 0，下 24px */
}

/* 用 margin-top 补齐"高度不是步长倍数"的元素（如图片、按钮） */
.media { margin-block: calc(var(--rhythm) * 1.5); }
:root {
  --leading: 1.5;                 /* line-height ratio */
  --rhythm: calc(1rem * var(--leading));   /* 24px = 3 × 8, the rhythm unit */
}

body {
  font-size: 1rem;                /* 16px */
  line-height: var(--rhythm);     /* ⭐ Key point ③: line height = rhythm unit, every body line lands on a tick */
}

h1 {
  /* ⭐ Key point ④: heading line heights must also be whole multiples, or the next block drifts */
  font-size: var(--step-4);                  /* about 44px */
  line-height: calc(var(--rhythm) * 2);      /* 48px = 6 × 8 */
  margin-block: 0 calc(var(--rhythm) * 1);   /* 0 above, 24px below */
}

/* Pad elements whose height is not a multiple (images, buttons) with margin */
.media { margin-block: calc(var(--rhythm) * 1.5); }

关键点解释：line-height 写无单位数值（1.5）是最稳的：它按各自字号计算，标题不会因为字号大而获得过大的行距；但为了共享节奏，这里反而要给标题显式指定绝对行高（48px）。这是一个真实的取舍：无单位行高利于阅读，绝对行高利于对齐。推荐做法是正文用无单位、标题与"要落格"的元素用绝对行高，并在注释里说明原因。

Key point: A unitless line-height (1.5) is the safest default: it scales with each font size so headings never inherit huge leading. Yet to share a rhythm we deliberately give headings an absolute line height (48px). That is a genuine trade-off: unitless is better for reading, absolute is better for alignment. The recommended pattern: unitless for body text, absolute for headings and for anything that must land on the grid — with the reason in a comment.
