第 2 章 文档流与盒模型：布局的物理定律

Chapter 2 Flow and the box model: the physics of layout

在动 Flexbox 和 Grid 之前，先把浏览器默认的布局算法搞清楚。绝大多数"莫名其妙"的布局 bug，都是因为违反了文档流的规则。

Before reaching for flexbox and grid, understand the layout algorithm the browser runs by default. Most "inexplicable" layout bugs come from breaking the rules of normal flow.

2.1 正常流：浏览器默认的布局算法

2.1 Normal flow: the browser’s default layout algorithm

在不写任何布局代码的情况下，浏览器已经在排版了。理解它在做什么，才知道什么时候需要干预。

Even with zero layout CSS, the browser is already laying things out. Understand what it is doing before you intervene.

打开一个只有 HTML 的页面，你看到的结果不是"没有样式"，而是正常流（normal flow）的结果：块级盒子从上到下依次堆叠，行内盒子从左到右排列并在行尾换行。这一套默认算法有三个关键性质，决定了后面所有布局手段的边界。

Open a page with HTML only and what you see is not "no styles" but the result of normal flow: block-level boxes stack top to bottom, inline boxes run left to right and wrap at the end of a line. This default algorithm has three properties that define the limits of every technique that follows.

性质一：高度由内容决定（content-driven height）

Property 1: height is content-driven

块级盒子的高度默认是 auto，含义是"容纳内容所需的高度"。这是文档流最重要的优点：你不需要知道内容有多长。文字变多、语言换成德语（词更长）、用户放大字号，盒子都会自己长大。
反过来，任何"把高度写死"的做法都在和这个性质对抗——这就是第 ③ 号病灶的根源：height: 120px 一旦遇上三行标题，内容就会溢出或重叠。

A block box’s height defaults to auto, meaning "whatever the content needs". This is normal flow’s most valuable property: you do not need to know how long the content is. More text, a longer language (German!), a user zooming in — the box grows by itself. Conversely, any hard-coded height fights this property, which is exactly the root of defect ③: a height: 120px header meets a three-line title and the content overflows or overlaps.

性质二：宽度默认撑满，但可以收缩到 min-content

Property 2: width fills the container, and can shrink to min-content

块级盒子的宽度默认 auto = 包含块宽度。所以"页面宽度"这件事在正常流里是自动的：只要祖先链没有溢出，子元素不会横向跑出去。这也是为什么能用正常流解决的布局，不要用绝对定位——绝对定位的盒子脱离这条约束，宽度收缩到内容宽，于是长标题会溢出容器。

A block box’s width defaults to auto = the containing block’s width. So "page width" is automatic in normal flow: as long as no ancestor overflows, children cannot run off horizontally. This is why anything normal flow can do should not be done with absolute positioning — an absolutely positioned box leaves that constraint, shrinks to its content width, and long titles then overflow it.

性质三：格式化上下文决定"谁和谁一起排版"

Property 3: formatting contexts decide who lays out with whom

正常流内部并不是一种排版方式，而是若干种格式化上下文（formatting context）的组合：块级格式化上下文（BFC）负责竖着堆，行内格式化上下文（IFC）负责横着排。display 的值就是在切换上下文的类型。

Normal flow is not one algorithm but a combination of formatting contexts: the block formatting context (BFC) stacks vertically, the inline formatting context (IFC) flows horizontally. Changing display is really switching which context applies.

display 值作用典型用途

🧠 理论支点：什么是 BFC，为什么它能"兜住"浮动元素？BFC 是一个独立的排版区域：区域内部元素的排布不影响外部，外部的浮动也不会侵入内部。所以给父元素一个 display: flow-root，父元素就会把内部浮动子元素的高度计入自身高度——这就是清除浮动（clearfix）的原理。历史上人们用 overflow: hidden 达到同样效果，但它有副作用（会裁掉阴影、影响 sticky），所以现代写法是 flow-root。CSS 2.1 §9.4.1「Block formatting contexts」；MDN「Block formatting context」
🧠 Theory: What is a BFC and why does it "contain" floats? A BFC is an independent layout region: what happens inside does not affect the outside, and outside floats cannot intrude. Giving a parent display: flow-root therefore makes it count the height of its floated children. That is the mechanism behind the classic clearfix. Historically people used overflow: hidden for the same effect, but it has side effects (it clips shadows and breaks sticky), so the modern idiom is flow-root.CSS 2.1 §9.4.1 "Block formatting contexts"; MDN "Block formatting context"
🧩 案例诊断：绝对定位让页面失去"自适应"能力v1 的 header：position:absolute; top:0; height:120px; width:100%，主体内容 margin-top:120px。三处违反文档流：①高度写死，标题三行时被裁掉；②宽度 100% 是相对"包含块"（最近的定位祖先）算的，一旦祖先不是全宽，header 就会短一截；③主体靠 margin-top:120px 手工对齐，header 一改高度就得同步改——两份信息描述同一件事，必然不同步。正确做法是把 header 放回正常流。
🧩 Case diagnosis: absolute positioning kills adaptivityThe v1 header uses position:absolute; top:0; height:120px; width:100% with the body pushed down by margin-top:120px. Three violations of normal flow: (1) a hard-coded height clips a three-line title; (2) width:100% resolves against the containing block — the nearest positioned ancestor — so it under-shoots as soon as that ancestor is not full width; (3) the body is aligned by hand with margin-top:120px, so every header change requires a matching manual edit. Two sources of truth for one fact will always drift. The fix is to put the header back into normal flow.

关键代码 ① 用 flow-root 建立独立的排版区域

Key code ① Create an independent layout region with flow-root

父元素高度塌陷的经典原因：子元素浮动后脱离正常流，父元素"看不见"它。

The classic cause of a collapsed parent: once a child floats it leaves normal flow, and the parent can no longer see it.

.media {
  /* ⭐ 关键点 ①：flow-root = "为一个新 BFC，但不要改变我这个元素自身的行为"
     对比 overflow:hidden：后者会裁掉阴影、破坏 sticky、影响滚动 */
  display: flow-root;
}

.media__cover { float: inline-start; margin-inline-end: var(--space-4); }

/* ❌ 老式写法的问题：
   .media { overflow: hidden; }   裁掉溢出的阴影/徽标
   .media::after { content:""; display:table; clear:both; }  —— 多余的空节点 */

/* ⭐ 关键点 ②：让"包含块"显式化 —— 需要定位参照时才加 position:relative */
.media { position: relative; }   /* 只有内部要放绝对定位元素时才需要 */
.media {
  /* ⭐ Key point ①: flow-root = "start a new BFC, but do not change my own outside behaviour"
     compare overflow:hidden: it clips shadows, breaks sticky and affects scrolling */
  display: flow-root;
}

.media__cover { float: inline-start; margin-inline-end: var(--space-4); }

/* ❌ why the legacy idiom is worse:
   .media { overflow: hidden; }   clips overflowing shadows and badges
   .media::after { content:""; display:table; clear:both; }  — an extra empty node */

/* ⭐ Key point ②: make the containing block explicit — add position:relative only when needed */
.media { position: relative; }   /* required only if something inside is absolutely positioned */

关键点解释：坑：position: relative 不是"免费的"。它会让元素成为定位包含块，内部任何 position:absolute 子元素都改为相对它定位。所以在深层组件里随手加 relative，会悄悄改变内部绝对定位元素的位置——这类 bug 极难排查。原则：只在确实需要作为定位参照时才加，并且加上注释说明"谁在依赖它"。

Key point: Pitfall: position: relative is not free. It makes the element a containing block for positioning, so every absolutely positioned descendant now resolves against it. Sprinkling relative through deep components silently moves those descendants — a bug that is very hard to trace. The rule: add it only when something genuinely needs it as a reference, and comment which element depends on it.

关键代码 ② 把"写死的高度"换成"内容驱动的高度"

Key code ② Replace hard-coded height with content-driven height

这是第 ③ 号病灶的正解：让 header 的高度由它的内容决定，同时保证内部元素垂直居中。

The fix for defect ③: let the header height follow its content while still centring it vertically.

.site-header {
  /* ❌ 病态：height: 120px; position: absolute; top: 0; */
  /* ⭐ 关键点 ③：min-height 给"最小舒适高度"，height 交给内容 */
  display: flex;
  align-items: center;          /* 交叉轴居中：内容再高也不会顶出去 */
  justify-content: space-between;
  gap: var(--space-4);
  min-height: 72px;             /* 只有一行时也保持手感，而不是硬性锁死 */
  padding-block: var(--space-3);/* ⭐ 关键点 ④：改用内边距提供呼吸，高度自然生长 */
  padding-inline: var(--space-5);
}
/* 不再需要 .site-main { margin-top: 120px } —— 正常流自己会接上去 */
.site-header {
  /* ❌ the defect: height: 120px; position: absolute; top: 0; */
  /* ⭐ Key point ③: min-height gives a comfortable floor; the content owns the real height */
  display: flex;
  align-items: center;          /* cross-axis centring: taller content still fits */
  justify-content: space-between;
  gap: var(--space-4);
  min-height: 72px;             /* keeps the feel for a single line without locking it */
  padding-block: var(--space-3);/* ⭐ Key point ④: padding provides the breathing room; height grows naturally */
  padding-inline: var(--space-5);
}
/* .site-main { margin-top: 120px } is no longer needed — normal flow follows automatically */

关键点解释：min-height + padding 的组合是"写死高度"的通用替代方案：它同时满足两个需求——视觉上的稳定（不会因为一行/两行而抖动）和结构上的自适应（内容变多就长大）。坑：如果一定要用 height，配上 overflow: auto 至少不会重叠，但那是"用滚动条掩盖问题"；真正的解法是让高度可变。

Key point: min-height plus padding is the general replacement for a fixed height: it satisfies both needs at once — visual stability (no jitter between one line and two) and structural adaptivity (it grows with content). Pitfall: if you must use height, add overflow: auto so it at least does not overlap — but that hides the problem behind a scrollbar. The real fix is a height that can change.

2.2 盒模型与外边距折叠

2.2 The box model and margin collapsing

一个元素的实际占地由四层构成；而垂直方向的两个外边距会合并成一个——这是布局里最反直觉的规则。

An element’s footprint has four layers, and two vertical margins merge into one — the most counter-intuitive rule in layout.

CSS 里没有一个叫"宽度"的东西，只有四个可以分别设置的层：内容（content）、内边距（padding）、边框（border）、外边距（margin）。搞清楚"你写的 width 到底指哪一层的宽"，能避免一多半的"算不对尺寸"问题。

There is no single thing called "width" in CSS — only four layers you can set separately: content, padding, border and margin. Knowing which layer your width refers to prevents most "my numbers do not add up" problems.

content-box 与 border-box

content-box vs border-box

默认的 box-sizing: content-box 表示 width 只算内容区：写 width: 300px; padding: 20px，元素实际占用 340px。这导致一个经典灾难：width: 50% 两栏再加 padding 就会超过 100%，横向滚动条出现。

The default box-sizing: content-box means width covers the content area only: width: 300px; padding: 20px occupies 340px in total. That produces the classic disaster: two width: 50% columns plus padding exceed 100% and a horizontal scrollbar appears.

box-sizing: border-box 让 width 包含 padding 与 border，于是"300px 就是 300px"。业界普遍做法是全局复位：

box-sizing: border-box makes width include padding and border, so "300px means 300px". The industry-wide convention is a global reset:

*, *::before, *::after { box-sizing: border-box; }
*, *::before, *::after { box-sizing: border-box; }

外边距折叠：三条规则

Margin collapsing: three rules

垂直方向上相邻的两个外边距会合并成一个，取其中较大者（不是相加）。三种情况：①相邻兄弟之间；②父元素与其第一个/最后一个子元素之间（没有 border/padding/内容隔开时）；③空的块级元素自身的上下外边距。

Two adjacent vertical margins merge into one, taking the larger value — not the sum. Three cases: (1) between adjacent siblings; (2) between a parent and its first/last child when nothing (border, padding, content) separates them; (3) the top and bottom margins of an empty block.

🧠 理论支点：为什么规范要这么设计？因为排版学里"段落之间的距离"本就应该是固定值，而不是"上一个段落的下边距 + 下一个段落的上边距"。如果不用折叠，你给每个 <p> 设 margin: 16px 0，段落之间会变成 32px，与页面其他地方的 16px 节奏冲突。折叠让"段落间距"这个概念可以被一个值直接表达。它的代价是：布局时"我写的 margin 去哪了"经常对不上，尤其在嵌套结构中。CSS 2.1 §8.3.1「Collapsing margins」
🧠 Theory: Why does the spec work this way? Because in typography the distance between paragraphs is a fixed value, not "previous bottom margin + next top margin". Without collapsing, margin: 16px 0 on every <p> would put 32px between paragraphs, clashing with the 16px rhythm elsewhere. Collapsing lets one value express the concept "paragraph spacing". The price is that in nested structures "where did my margin go?" is a common question.CSS 2.1 §8.3.1 "Collapsing margins"

实用建议：现代布局里最好尽量避免依赖外边距折叠。用 gap 表达组内间距、用 padding 或单向的 margin-block-start 表达组间间距，语义更清楚，也不会出现折叠带来的意外。需要精确控制时，display: flex/grid 的容器内部根本不发生折叠——这也是它们更好预测的原因之一。

Practical advice: in modern layout, avoid depending on margin collapsing. Use gap for within-group spacing and padding or one-directional margin-block-start for between-group spacing: the intent is clearer and collapse cannot surprise you. When you need precision, note that collapsing does not happen inside flex or grid containers — one more reason they are easier to reason about.

🧩 案例诊断：为什么"卡片间距看起来不一样"v1 里给卡片写了 margin-bottom: 21px，给区块写了 margin-top: 37px。两者相遇时折叠成 37px，于是"卡片之间"和"区块之间"变成了同一个值——设计意图（两种不同关系）被浏览器合并成了一种。修复：容器改成 flex + gap: 32px，区块间距用 padding-block，两种间距各归其位，再也不会互相吞并。
🧩 Case diagnosis: why the card gaps look inconsistentv1 sets margin-bottom: 21px on cards and margin-top: 37px on sections. Where they meet they collapse to 37px, so "between cards" and "between sections" become the same number — the design intent (two different relationships) is merged into one by the browser. Fix: make the container a flex container with gap: 32px and express section spacing with padding-block; each spacing then keeps its own meaning and can no longer swallow the other.

关键代码 ① 全局 padding 复位与尺寸可预期

Key code ① A predictable box everywhere

三行复位，让"写的宽度"等于"占的宽度"，团队里所有人对尺寸的理解一致。

Three lines of reset so "the width I wrote" equals "the width it occupies" — one shared understanding across the team.

/* ⭐ 关键点 ①：全局 border-box —— 宽度包含内边距与边框 */
*, *::before, *::after { box-sizing: border-box; }

/* ⭐ 关键点 ②：让图片/视频默认不撑破容器，这是"响应式的地板" */
img, video, svg { display: block; max-width: 100%; height: auto; }

.card { width: 300px; padding: var(--space-5); border: 1px solid var(--ink-200); }
/* content-box 下实际占 300 + 48 + 2 = 350px
   border-box 下实际占 300px，内容区 250px —— 这才是设计稿的语义 */
/* ⭐ Key point ①: global border-box — width includes padding and border */
*, *::before, *::after { box-sizing: border-box; }

/* ⭐ Key point ②: images/videos cannot break their container by default — the floor of responsiveness */
img, video, svg { display: block; max-width: 100%; height: auto; }

.card { width: 300px; padding: var(--space-5); border: 1px solid var(--ink-200); }
/* with content-box this occupies 300 + 48 + 2 = 350px
   with border-box it occupies 300px, content area 250px — which is what the design file means */

关键点解释：img { display: block } 这一句经常被忽略：行内图片会带来基线以下的空隙（因为行内格式化上下文要为字母下伸部留空间），于是图片下方莫名多出 4–6px 的白边。max-width: 100% 则是"图片不撑破容器"的必备句——注意它也意味着图片会被缩小但不会被放大，所以小图不会在宽屏上被拉糊。

Key point: img { display: block } is often skipped: an inline image sits on the text baseline, so the inline formatting context reserves room for descenders and you get 4–6px of mystery gap under the image. max-width: 100% is the must-have "images cannot break their container" line — note it also means images shrink but never upscale, so small images do not get stretched and blurry on wide screens.

关键代码 ② 用 gap 代替 margin，告别折叠

Key code ② Use gap instead of margins and forget collapsing

把"间距"从"每个元素的属性"改成"容器的属性"，间距就变得集中、可预测、不会折叠。

Move spacing from "a property of each element" to "a property of the container" and it becomes centralised, predictable and collapse-free.

.card-grid {
  display: grid;
  /* ⭐ 关键点 ③：一个 gap 同时表达"行间距"和"列间距"，且永不折叠 */
  gap: var(--space-6);
  /* 自适应列数：见第 4 章 */
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
}

.section + .section {
  /* ⭐ 关键点 ④：只用单向 margin-block-start，杜绝"上下都写、结果被折叠" */
  margin-block-start: var(--space-8);
}

/* ❌ 病态写法：上下都写 margin，间距语义被折叠吃掉
.card { margin-bottom: 21px; }
.section { margin-top: 37px; }   /* 结果只有 37px，还有 21px 消失了 */
.card-grid {
  display: grid;
  /* ⭐ Key point ③: one gap expresses both row and column spacing, and never collapses */
  gap: var(--space-6);
  /* adaptive column count: see Chapter 4 */
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
}

.section + .section {
  /* ⭐ Key point ④: only a one-directional margin-block-start — never both sides that then collapse */
  margin-block-start: var(--space-8);
}

/* ❌ the broken version: margins on both sides, so the intent is eaten by collapsing
.card { margin-bottom: 21px; }
.section { margin-top: 37px; }   /* the result is 37px — 21px vanished */

关键点解释：这条对比很值得记住：同样的意图，两种写法的结果差了 21px，而且第二种只在"这两个元素恰好相邻"时才出问题——换个上下文（中间插了一个元素）折叠不再发生，间距又变了。这种"依赖上下文的间距"是布局 bug 的高发区。gap 与单向 margin 的共同点是：结果只取决于你写的那一个值。

Key point: Worth memorising: the same intent, two implementations, 21px apart — and the broken one only misbehaves when those two elements happen to be adjacent. Insert something between them and collapsing stops, so the spacing changes again. Spacing whose result depends on context is where layout bugs breed. Both gap and a one-directional margin share the same virtue: the result depends only on the one value you wrote.

2.3 脱离文档流：定位、层叠与粘性

2.3 Leaving the flow: positioning, stacking and sticky

绝对定位不是"想放哪放哪"，它是在声明"这个盒子不参与排版"。理解代价，才用得对。

Absolute positioning is not "put it anywhere"; it declares "this box takes no part in layout". Understand the cost before you use it.

position 的五个值，本质上是在回答两个问题：这个盒子还参与正常流吗？以及它相对谁定位？

The five values of position really answer two questions: does this box still participate in normal flow? and what is it positioned against?

绝对定位真正的代价：它同时拿走三样东西

The real cost of absolute positioning: it takes away three things

  • 不占位：其他元素不会为它让路，所以它与内容重叠几乎是必然的——只要内容长度变化。
  • 失去父元素的高度贡献：父元素若没有其他内容，高度会塌成 0。
  • 宽度收缩到内容：除非显式写 inset 或宽度，绝对定位元素不会自动撑满，长内容会溢出。
  • It takes no space: siblings do not make room for it, so overlap is almost guaranteed as soon as content length changes.
  • It stops contributing height to its parent: with no other content the parent collapses to zero.
  • Its width shrinks to content: unless you set inset or a width, an absolutely positioned box does not fill anything, so long content overflows.

层叠上下文：为什么 z-index 有时"不生效"

Stacking contexts: why z-index sometimes "does not work"

z-index 只在同一个层叠上下文内比较。而很多属性会创建新的层叠上下文：position 非 static 且 z-index 非 auto、opacity < 1、transform 非 none、filter、will-change、isolation: isolate 等。一旦父元素因为 transform 或 opacity 创建了层叠上下文，子元素的 z-index: 9999 就再也盖不过父元素的兄弟了。

z-index is only compared within one stacking context. Many properties create a new stacking context: position other than static with a non-auto z-index, opacity < 1, non-none transform, filter, will-change, isolation: isolate and more. Once a parent creates a stacking context via transform or opacity, a child’s z-index: 9999 can never escape above the parent’s siblings.

sticky 为什么经常"失效"

Why sticky so often "does not work"

  • 祖先元素有 overflow: hidden / auto / scroll：sticky 被限制在那个滚动容器里，看起来像没生效。
  • 没有指定 top（或 bottom）：sticky 需要一个"门槛值"才知道何时开始吸附。
  • 父元素高度等于自身高度（常见于 flex 的 align-items: center）：元素没有可移动的余地。
  • 被后续兄弟元素盖住：sticky 元素没有创建层叠上下文时，后出现的兄弟可能盖在它上面。
  • An ancestor has overflow: hidden / auto / scroll: sticky is confined to that scroll container and appears dead.
  • No top (or bottom) is set: sticky needs a threshold to know when to stick.
  • The parent is exactly as tall as the element itself (common with flex align-items: center): there is no room to move.
  • A later sibling paints over it: without its own stacking context the sticky element can be covered by a later sibling.

判断口诀：sticky = "在父元素的地盘内，跟着滚动容器吸附"。所以问三个问题：滚动容器是谁（有没有 overflow）？吸附门槛是多少（top）？父元素的地盘有多大（高度是否足够）？这三个问题的答案决定了它能不能工作。

Rule of thumb: sticky means "stick within the parent’s territory, following the scrolling ancestor". So ask three questions: who is the scroller (any overflow)? What is the threshold (top)? How big is the parent’s territory (enough height)? Those three answers decide whether it works.

🧩 案例诊断：吸顶导航"时好时坏"v1 把导航包在一个 .page-wrap { overflow: hidden } 里（本意是防止横向溢出），结果 position: sticky 完全失效。开发者改成 position: fixed，问题更大：fixed 脱离文档流，导航高度不再撑开页面，首屏内容被盖住，只能靠 margin-top 手工补。正解：去掉那个 overflow: hidden（改用 overflow-x: clip），保留 sticky——它既参与正常流（不遮盖内容），又能吸附。
🧩 Case diagnosis: a sticky nav that works "sometimes"v1 wraps the nav in .page-wrap { overflow: hidden } (intended to prevent horizontal overflow), which kills position: sticky entirely. Switching to position: fixed is worse: fixed leaves normal flow, so the nav no longer pushes the page down, the first screen sits under it and you have to patch it with margin-top. The fix: remove that overflow: hidden (use overflow-x: clip instead) and keep sticky — it stays in normal flow, so it never covers content, yet it still sticks.

关键代码 ① 吸顶导航：五条约束缺一不可

Key code ① A sticky header: five constraints, all required

sticky 的失效几乎总是"环境问题"而不是 sticky 本身的问题。

When sticky fails it is almost always an environment problem, not a sticky problem.

.site-header {
  /* ⭐ 关键点 ①：门槛值必须有，否则元素不知道何时开始吸附 */
  position: sticky;
  top: 0;

  /* ⭐ 关键点 ②：自己建立层叠上下文，防止被后续兄弟盖住 */
  z-index: 10;
  background: #fff;          /* 没有底色，滚动时内容会从下面"透"上来 */

  /* ⭐ 关键点 ③：吸顶元素不要用 transform 定位祖先无关，
     但祖先若有 transform，fixed 会改为相对它定位（sticky 不受影响，但排查时要知道） */
}

/* ⭐ 关键点 ④：祖先链上不能有 overflow: hidden/auto/scroll */
.page { overflow-x: clip; }   /* 用 clip 代替 hidden：不会创建滚动容器，sticky 依然有效 */
/* ❌ .page { overflow: hidden; }  → sticky 直接失效 */
.site-header {
  /* ⭐ Key point ①: the threshold is mandatory, or the element never knows when to stick */
  position: sticky;
  top: 0;

  /* ⭐ Key point ②: create your own stacking context so later siblings cannot paint over you */
  z-index: 10;
  background: #fff;          /* without a background, content shows through while scrolling */

  /* ⭐ Key point ③: a transformed ancestor does not break sticky but does break fixed —
     know this when debugging which of the two you are looking at */
}

/* ⭐ Key point ④: no overflow: hidden/auto/scroll anywhere in the ancestor chain */
.page { overflow-x: clip; }   /* use clip instead of hidden: no scroll container, so sticky still works */
/* ❌ .page { overflow: hidden; }  → sticky dies immediately */

关键点解释：overflow-x: clip 是近年的重要补充：它能防止横向溢出，却不创建滚动容器，因此不会破坏 sticky 和 position: fixed 的包含块。这也解释了为什么"用 overflow: hidden 兜住横向溢出"是个坏习惯——它会在别处引发 sticy 失效。坑：clip 不能滚动，所以如果你真的需要滚动，那要用 auto 并接受 sticky 被限制在容器内。

Key point: overflow-x: clip is an important recent addition: it prevents horizontal overflow while not creating a scroll container, so it neither breaks sticky nor changes the containing block for position: fixed. That is why "wrap everything in overflow: hidden" is a bad habit — it breaks sticky somewhere else. Pitfall: clip cannot scroll, so if you genuinely need scrolling, use auto and accept that sticky is confined to the container.

关键代码 ② 绝对定位只用于"装饰与浮层"

Key code ② Reserve absolute positioning for decoration and overlays

把"绝对定位"限定在不会影响其他内容位置的地方，代价就消失了。

Confine absolute positioning to places that cannot move other content, and the cost disappears.

.card {
  /* ⭐ 关键点 ⑤：父元素成为定位参照（仅此一处需要 relative） */
  position: relative;
}

.card__badge {
  /* ⭐ 关键点 ⑥：装饰性元素不参与排版，重叠也不会挤坏内容 */
  position: absolute;
  inset-block-start: var(--space-3);
  inset-inline-end: var(--space-3);
  /* 用逻辑属性 inset-*，而不是 top/right —— 书写方向变化时自动跟随 */
  pointer-events: none;      /* 装饰物不该抢走点击 */
}

/* ⭐ 关键点 ⑦：需要"覆盖一层"时，用 grid 让两者落在同一个格子，而不是绝对定位 */
.hero { display: grid; }
.hero > * { grid-area: 1 / 1; }   /* 图片与文字叠在同一格，且都参与排版 */
.card {
  /* ⭐ Key point ⑤: the card becomes the positioning reference (the one place relative is needed) */
  position: relative;
}

.card__badge {
  /* ⭐ Key point ⑥: decoration takes no part in layout, so overlap cannot break the content */
  position: absolute;
  inset-block-start: var(--space-3);
  inset-inline-end: var(--space-3);
  /* logical inset-* instead of top/right — follows the writing direction automatically */
  pointer-events: none;      /* decoration should not steal clicks */
}

/* ⭐ Key point ⑦: to overlay two things, stack them in one grid cell instead of using absolute */
.hero { display: grid; }
.hero > * { grid-area: 1 / 1; }   /* image and text share a cell and both stay in flow */

关键点解释：最后一条是很有价值的技巧："叠放"未必需要绝对定位。用 grid-area: 1 / 1 让两个元素落在同一格，它们仍然参与排版——父元素的高度由两者中更高的那个决定，而不是塌成 0。这在"图片上叠文字"的场景里比绝对定位健壮得多：文字变多时图片不会被压出容器。

Key point: The last one is a valuable trick: overlaying does not require absolute positioning. Give both children grid-area: 1 / 1 and they share a grid cell while remaining in flow — the parent is as tall as the taller child instead of collapsing to zero. For "text over image" this is far more robust than absolute positioning: more text never pushes the image out of its container.
