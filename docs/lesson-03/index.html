第 3 章 一维布局：Flexbox

Chapter 3 One-dimensional layout: flexbox

Flexbox 解决的是"一行/一列里，元素怎么分配空间、怎么对齐"。它的难点不在语法，而在主轴与交叉轴的心智模型。

Flexbox answers one question: inside a single row or column, how do items share space and line up? The difficulty is not syntax but the mental model of main axis versus cross axis.

3.1 主轴与交叉轴：一个可以旋转的坐标系

3.1 Main and cross axis: a coordinate system that rotates

justify-content 和 align-items「谁管哪个方向」的问题，答案取决于 flex-direction。

Which direction do justify-content and align-items control? The answer depends on flex-direction.

把 flex 容器想成一个局部坐标系：容器定义一个主轴（main axis）和一个与它垂直的交叉轴（cross axis）。所有对齐属性都是相对这两个轴说的，而不是相对"上下左右"说的。

Think of a flex container as a local coordinate system: it defines a main axis and a perpendicular cross axis. Every alignment property refers to those two axes, not to "up, down, left, right".

属性作用方向备注
justify-content主轴上的对齐与空间分配行（row）时管水平，列（column）时管垂直
align-items交叉轴上的对齐stretch（默认）会拉伸元素，常导致"卡片莫名变高"
flex-direction决定主轴方向改它等于旋转整个坐标系
gap沿主轴 / 交叉轴的项目间距比给子元素加 margin 更干净，不会有折叠
PropertyActs onNote
justify-contentAlignment and space on the main axisHorizontal for row, vertical for column
align-itemsAlignment on the cross axisstretch (the default) stretches items, which often causes "why is my card taller"
flex-directionDecides the main axisChanging it rotates the whole coordinate system
gapSpacing between items on both axesCleaner than margins on children, and never collapses
🧠 理论支点：为什么用"轴"而不是"上下左右"？因为 CSS 的书写模式可能改变（横排、竖排，从左到右、从右到左）。如果属性叫 align-horizontal，在竖排文字里就没有意义了。用主轴/交叉轴，同一套属性可以在任何书写方向和任何 flex-direction 下保持一致的语义：justify 管"沿内容流动方向"，align 管"垂直于流动方向"。这也是逻辑属性（margin-inline-start）背后的同一套思路。CSS Flexible Box Layout Module Level 1 §2「Flex Layout Box Model and Terminology」
🧠 Theory: Why axes rather than up/down/left/right? Because writing modes change (horizontal or vertical, left-to-right or right-to-left). A property named align-horizontal would be meaningless in vertical text. With main and cross axes the same properties keep one consistent meaning across writing modes and flex-direction values: justify acts along the direction content flows, align acts across it. The same idea underlies logical properties such as margin-inline-start.CSS Flexible Box Layout Module Level 1 §2 "Flex Layout Box Model and Terminology"

三条最容易记错的规则

Three rules people most often get wrong

  • align-items 默认值是 stretch，不是 flex-start。所以一行 flex 子元素默认会被拉成等高——这既是"等高卡片"的免费实现，也是"为什么我的按钮被拉长了"的原因。
  • 子元素的 margin: auto 会把剩余空间吃掉。这是实现"左边 logo、右边菜单"最简单的方法：给菜单 margin-inline-start: auto，它就被推到最右边，不需要 justify-content: space-between。
  • flex 容器会忽略子元素的 float，并且子元素的 display 会被"块化"（display: inline 的 span 变成可设宽高的 flex item）。
  • align-items defaults to stretch, not flex-start. Children in a flex row are therefore stretched to equal height by default — both the free way to get equal-height cards and the reason "why is my button stretched".
  • margin: auto on a child absorbs the leftover space. This is the simplest way to get "logo left, menu right": give the menu margin-inline-start: auto and it is pushed to the far end without needing justify-content: space-between.
  • A flex container ignores float on its children and blockifies their display: a display: inline span becomes a flex item that accepts width and height.
🧩 案例诊断：问题 ④ 靠空格对齐导航v1 的导航是这样写的：<span>课程</span>&nbsp;&nbsp;&nbsp;<span>讲师</span>，并且给"课程"加了 width: 60px。"讲师"两个字和"价格"两个字的宽度只差几像素，但对齐是靠空格凑的，所以：①改成英文（Courses / Instructors）立刻错位；②用户放大字号后空格宽度不变但文字变宽，再次错位；③键盘用户看不出焦点在哪。改用 flex 之后，gap 负责间距、align-items: center 负责垂直居中，文案改成任何语言、任何长度都不会错位。
🧩 Case diagnosis: defect ④ space-hacked navigationThe v1 nav reads <span>Courses</span>&nbsp;&nbsp;&nbsp;<span>Instructors</span> with width: 60px on the first item. Spaces, not layout, hold the alignment, so: (1) switching the copy to another language instantly breaks it; (2) when a user increases the font size the spaces stay the same width while the text grows, breaking it again; (3) keyboard users cannot see where focus is. With flex, gap owns the spacing and align-items: center owns vertical centring, so no copy change in any language can misalign it.

关键代码 ① 导航栏：五行 CSS 替代所有空格

Key code ① A navbar: five lines instead of every spacer

用布局属性表达结构关系，而不是用空格"画"出结构。

Express structure with layout properties instead of "drawing" it with spaces.

.nav {
  /* ⭐ 关键点 ①：先声明"这是一个一维排布" */
  display: flex;
  align-items: center;              /* 交叉轴居中：文字与按钮的中线对齐 */
  gap: var(--space-5);              /* ⭐ 关键点 ②：间距由容器统一管理，不写在子元素上 */
}

/* ⭐ 关键点 ③：把某一部分推到另一端（logo 左、菜单右）
   比 justify-content: space-between 更精确：中间的元素不会被"平均拉散" */
.nav__menu { margin-inline-start: auto; }

/* 子元素不再需要 width / 空格 */
.nav a { padding: var(--space-2) var(--space-3); }
.nav {
  /* ⭐ Key point ①: first declare "this lays out in one dimension" */
  display: flex;
  align-items: center;              /* cross-axis centring: text and buttons share a midline */
  gap: var(--space-5);              /* ⭐ Key point ②: spacing is owned by the container, not the children */
}

/* ⭐ Key point ③: push one part to the far end (logo left, menu right).
   More precise than justify-content: space-between, which spreads middle items apart */
.nav__menu { margin-inline-start: auto; }

/* children no longer need widths or spacer characters */
.nav a { padding: var(--space-2) var(--space-3); }

关键点解释：gap 是 flex 布局里"最像设计意图"的属性：它描述的是元素之间的关系，而不是某个元素的个体属性。这与第 1 章讲的"把间距命名成关系"是同一件事。坑：gap 只作用于 flex/grid 容器直接子元素之间，不会穿透到更深层；另外它不会像 margin 那样"折叠"，所以从 margin 迁到 gap 时数值通常要调小一些。

Key point: gap is the property that best matches design intent in a flex layout: it describes a relationship between items rather than a property of one item — the same idea as "naming spacing by relationship" in Chapter 1. Pitfall: gap only applies between the direct children of a flex or grid container and does not reach deeper; and since it never collapses like margins do, values usually need to shrink slightly when migrating from margin to gap.

关键代码 ② align-items 与 align-self：什么时候需要"反悔"

Key code ② align-items and align-self: when to opt out

父元素默认 stretch 会拉伸所有子元素；个别子元素想"不参与拉伸"时用 align-self。

The parent’s default stretch pulls every child to full height; a child that wants out uses align-self.

.card-row {
  display: flex;
  gap: var(--space-5);
  align-items: stretch;   /* 默认值：三张卡片等高 —— 这就是"等高卡片"的实现方式 */
}

/* ⭐ 关键点 ④：单个元素退出拉伸，例如一行里的"了解更多"链接按钮 */
.card__link { align-self: center; }

/* ⭐ 关键点 ⑤：卡片内部用 column + flex:1 让"页脚贴底" */
.card {
  display: flex;
  flex-direction: column;   /* 主轴变成垂直方向，justify 也随之变成"管垂直" */
  gap: var(--space-2);
}
.card__body { flex: 1; }    /* 正文吃掉剩余高度，把按钮推到卡片底部 */
.card__cta { margin-block-start: auto; }   /* 或者用 auto margin，效果等价 */
.card-row {
  display: flex;
  gap: var(--space-5);
  align-items: stretch;   /* the default: three cards of equal height — that is equal-height cards for free */
}

/* ⭐ Key point ④: a single item opts out of stretching, e.g. a "learn more" link inside a row */
.card__link { align-self: center; }

/* ⭐ Key point ⑤: inside a card, column + flex:1 makes the footer sit at the bottom */
.card {
  display: flex;
  flex-direction: column;   /* the main axis becomes vertical, so justify now acts vertically too */
  gap: var(--space-2);
}
.card__body { flex: 1; }    /* the body absorbs the leftover height, pushing the button down */
.card__cta { margin-block-start: auto; }   /* an auto margin does the same job */

关键点解释：flex-direction: column 之后，justify-content 就变成"垂直方向"了——这是 3.1 的核心。很多人在卡片里写 justify-content: center 想水平居中，结果发现内容上下居中了，就是因为主轴已经转成了纵向。记忆法：justify 永远跟着内容流动的方向，align 永远垂直于它。

Key point: After flex-direction: column, justify-content acts vertically — the core point of 3.1. Many people write justify-content: center inside a card expecting horizontal centring and find the content centred vertically instead, precisely because the main axis rotated. Mnemonic: justify always follows the direction content flows; align is always across it.

3.2 空间分配：grow / shrink / basis 与溢出陷阱

3.2 Space distribution: grow, shrink, basis and the overflow trap

flex 的"弹性"到底是怎么算的？以及那个让无数人踩坑的 min-width: auto。

How exactly does flex compute "flexibility"? And the min-width: auto that has tripped up everyone.

当所有项目的基准尺寸加起来的和小于容器宽度时，多出来的空间叫剩余空间（free space），按 flex-grow 的比例分配；当它们大于容器宽度时，超出量按 flex-shrink 的加权比例收缩。这条"先算剩余空间，再按比例分"的逻辑，就是 flex 弹性分配的完整规则。

When the sum of the items’ base sizes is less than the container, the surplus is free space, distributed in proportion to flex-grow. When the sum is greater, the excess is removed in proportion to flex-shrink (weighted). "Compute the leftover, then share it by ratio" is the whole rule.

写法等价于语义
flex: 11 1 0%忽略内容宽度，所有同级元素平均分配容器宽度
flex: auto1 1 auto以内容宽度为基准，再把剩余空间平均分掉；内容长的更宽
flex: none0 0 auto不伸不缩，完全按内容尺寸（图标、头像常用）
flex: 22 1 0%与 flex: 1 的兄弟按 2:1 分配宽度
ShorthandEqualsMeaning
flex: 11 1 0%Ignores content width; all siblings share the container equally
flex: auto1 1 autoStarts from content width, then shares the leftover; longer content ends up wider
flex: none0 0 autoNeither grows nor shrinks: purely content-sized (icons, avatars)
flex: 22 1 0%Takes 2:1 of the width against a flex: 1 sibling

最容易搞错的一点：flex: 1（basis 为 0）和 flex: auto（basis 为内容宽）在"内容长度不均匀"时结果完全不同。做三栏等宽布局要用 flex: 1；做"侧栏固定、主区自适应"要用 flex: 1 配 flex: none。不要用 flex: auto 做等宽——只要有一栏文字多，它就会更宽。

The most common mistake: flex: 1 (basis 0) and flex: auto (basis = content width) behave completely differently when content lengths differ. Use flex: 1 for equal columns; use flex: 1 plus flex: none for a fixed sidebar with a fluid main area. Never use flex: auto for equal widths — one longer column will take more space.

溢出陷阱：min-width: auto

The overflow trap: min-width: auto

规定里，flex 项目有一个隐含的最小尺寸限制：min-width: auto，含义是"不能小于内容的最小尺寸（min-content）"。所以当一个 flex 项目里有超长单词、长 URL、或者一个宽的 <pre> 时，它不会收缩到容器以内，而是把容器撑破，整页出现横向滚动条。

Per spec a flex item has an implicit minimum size: min-width: auto, meaning "never smaller than the content’s min-content size". So when an item contains a long unbreakable word, a long URL or a wide <pre>, it refuses to shrink below that and blows the container open, producing a page-wide horizontal scrollbar.

/* 修复：显式把最小尺寸归零，允许收缩到比内容更窄 */
.flex-child { min-width: 0; }      /* 横向布局 */
.flex-child { min-height: 0; }     /* 纵向布局（比如内部要滚动的列表） */
/* 之后再配合 overflow: hidden / text-overflow: ellipsis / overflow-wrap: anywhere */
/* Fix: zero out the minimum explicitly so it may shrink narrower than its content */
.flex-child { min-width: 0; }      /* horizontal layout */
.flex-child { min-height: 0; }     /* vertical layout (e.g. a scrollable inner list) */
/* then add overflow: hidden / text-overflow: ellipsis / overflow-wrap: anywhere */
🧠 理论支点：为什么会有这个"反直觉"的默认值？因为对绝大多数内容来说，"被压到看不见"比"撑开容器"更糟：文字被裁掉是信息丢失，而横向滚动至少内容还在。所以规范选择了"宁可溢出也不压扁文字"。理解了这个取舍，就知道 min-width: 0 不是"hack"，而是明确告诉浏览器"这里被裁掉是可以接受的"。CSS Flexbox §4.5「Automatic Minimum Size of Flex Items」
🧠 Theory: Why this counter-intuitive default? For most content, "squeezed out of sight" is worse than "overflows the box": clipped text is information loss, whereas a horizontal scrollbar at least keeps the content. The spec chose to overflow rather than crush text. Once you see that trade-off, min-width: 0 is not a hack — it is explicitly telling the browser that clipping is acceptable here.CSS Flexbox §4.5 "Automatic Minimum Size of Flex Items"
🧩 案例诊断：卡片被一个长单词撑破v1 的课程卡里有课程英文名 LayoutConsistencyChecklist，卡片一行三张。窄屏时这一张卡片里的长单词不肯收缩，把整个卡片行撑到 780px，整页出现横向滚动条（这正是第 ⑦ 号病灶的来源之一）。修复只要三行：.card { min-width: 0 }、标题用 overflow-wrap: anywhere、配合 text-overflow: ellipsis 截断。记住：只要用了 flex/grid，就要给"可能装长内容"的子元素加 min-width: 0。
🧩 Case diagnosis: one long word breaks a cardA v1 course card contains the long course code LayoutConsistencyChecklist, three cards to a row. On narrow screens that word refuses to shrink and pushes the row to 780px, so the whole page grows a horizontal scrollbar — one of the sources of defect ⑦. The fix is three lines: .card { min-width: 0 }, overflow-wrap: anywhere on the title, and text-overflow: ellipsis to truncate. Remember: whenever you use flex or grid, add min-width: 0 to any child that might hold long content.

关键代码 ① 三行写出"三栏等宽 + 侧栏固定"

Key code ① Three lines for equal columns plus a fixed sidebar

把"谁伸缩、谁固定"写成一行声明，而不是靠百分比猜。

Declare who flexes and who stays fixed in one line each instead of guessing percentages.

.sidebar { flex: none; width: 16rem; }   /* ⭐ 关键点 ①：不伸不缩，尺寸明确 */
.main    { flex: 1; min-width: 0; }     /* ⭐ 关键点 ②：吃掉剩余宽度，并允许收缩 */

/* 三栏等宽（忽略内容长度的差异） */
.col { flex: 1 1 0; min-width: 0; }
/* ❌ .col { flex: 1 1 auto }  → 文字多的那一栏会明显更宽 */

/* 固定比例：主区 2 份，侧区 1 份 */
.main { flex: 2 1 0; }
.aside { flex: 1 1 0; }
.sidebar { flex: none; width: 16rem; }   /* ⭐ Key point ①: no flexing, explicit size */
.main    { flex: 1; min-width: 0; }     /* ⭐ Key point ②: takes the leftover width and may shrink */

/* three equal columns (content length ignored) */
.col { flex: 1 1 0; min-width: 0; }
/* ❌ .col { flex: 1 1 auto }  → the column with more text ends up visibly wider */

/* fixed ratio: main area takes 2 shares, aside 1 */
.main { flex: 2 1 0; }
.aside { flex: 1 1 0; }

关键点解释：注意 flex: none; width: 16rem 这种"固定栏"的写法：用 rem 而不是 px 让它在用户缩放字号时同步变化（WCAG 1.4.4）。坑：固定宽度栏在 320px 屏幕上会吃掉全部宽度，所以必须配合断点或内在布局（第 5 章）把它改成纵向堆叠——这也是"响应式不能只靠 flex 弹性"的原因。

Key point: Note the flex: none; width: 16rem pattern for a fixed column: rem rather than px so it scales with the user’s font size (WCAG 1.4.4). Pitfall: a fixed-width column eats the whole screen at 320px, so it must be paired with a breakpoint or with intrinsic layout (Chapter 5) to stack vertically. This is why "responsiveness cannot rely on flex alone".

关键代码 ② 修复被长内容撑破的 flex 项目

Key code ② Fixing a flex item that long content blows open

这是 flex 布局最常被搜索的一个问题，答案就是三行。

This is the single most-searched flexbox problem, and the answer is three lines.

.card {
  flex: 1 1 0;
  /* ⭐ 关键点 ③：解除"最小尺寸 = 内容最小尺寸"的限制，允许收缩 */
  min-width: 0;
  /* 纵向 flex 或 grid 里要写 min-height: 0，原因完全相同 */
}

.card__title {
  /* ⭐ 关键点 ④：长英文单词/URL 允许在任意位置断行 */
  overflow-wrap: anywhere;
  /* 想要单行省略号的话： */
  /* white-space: nowrap; overflow: hidden; text-overflow: ellipsis; */
}

/* 用一个长单词做回归测试，避免以后再踩 */
/* <h4 class="card__title">LayoutConsistencyChecklist</h4> */
.card {
  flex: 1 1 0;
  /* ⭐ Key point ③: lift the "minimum size = content minimum" restriction so it can shrink */
  min-width: 0;
  /* inside a column flex or grid, write min-height: 0 — exactly the same reason */
}

.card__title {
  /* ⭐ Key point ④: allow long words and URLs to break anywhere */
  overflow-wrap: anywhere;
  /* for a single-line ellipsis instead: */
  /* white-space: nowrap; overflow: hidden; text-overflow: ellipsis; */
}

/* keep a long word around as a regression test so this never comes back */
/* <h4 class="card__title">LayoutConsistencyChecklist</h4> */

关键点解释：overflow-wrap: anywhere 与 word-break: break-all 的区别值得记住：前者只在必要时断词（优先按空格断行，最后手段才切断单词），后者会把所有单词都切碎。中文排版里因为汉字本身可断，两者差别不明显；但只要页面里有英文单词、URL、代码标识符，就该用 anywhere。另外 overflow-wrap: anywhere 会参与最小尺寸计算，这是它比 break-word 更适合 flex 场景的原因。

Key point: Worth remembering the difference between overflow-wrap: anywhere and word-break: break-all: the former breaks words only when necessary (preferring spaces, splitting a word as a last resort), while the latter shreds every word. In Chinese typography the difference is subtle because characters break naturally, but as soon as a page contains English words, URLs or code identifiers, use anywhere. It also participates in minimum-size computation, which is why it suits flex better than break-word.

3.3 四个经典模板与破坏性测试

3.3 Four classic templates and a stress test

媒体对象、等高卡片、页脚贴底、经典双栏——这四类布局覆盖了绝大多数真实需求。

The media object, equal-height cards, the sticky footer and the classic two-column layout cover the great majority of real requirements.

与其背属性，不如记模板。下面四个模板是 flex 布局的"成语"：一旦认出场景属于哪个模板，代码几乎不需要思考。更重要的是，每个模板都要经过破坏性测试——注入超长文案、长单词、超宽图片，看它是否还成立。

Rather than memorising properties, memorise templates. The four below are flexbox idioms: once you recognise which template a situation is, the code needs almost no thought. More importantly, every template must survive a stress test — inject very long copy, a long word, an oversized image, and see whether it still holds.

模板 1：媒体对象（Media Object）

Template 1: the media object

左边一个固定尺寸的图/头像，右边自适应文字。要点：图用 flex: none（不许被压缩），文字容器用 flex: 1; min-width: 0。这是最古老也最常用的布局模式之一，Nicole Sullivan 在 2010 年把它命名为 "media object"。

A fixed-size image or avatar on one side, fluid text on the other. The key: the image gets flex: none (never squeezed), the text container gets flex: 1; min-width: 0. One of the oldest and most reused patterns, named the "media object" by Nicole Sullivan in 2010.

模板 2：等高卡片（Equal-height cards）

Template 2: equal-height cards

一行 N 张卡片，高度自动对齐，且卡片内的按钮都在底部对齐。要点：外层 align-items: stretch（默认值，不用写），每张卡片是 flex-direction: column，卡片的正文区 flex: 1。这样即使某张卡片文字多两行，按钮也能"贴"在底部。

N cards in a row, equalised in height, with each card’s button aligned to its bottom. The key: the row uses align-items: stretch (the default, so no need to write it), each card is flex-direction: column, and the card body is flex: 1. A card with two extra lines of text still keeps its button pinned to the bottom.

模板 3：页脚贴底（Sticky footer）

Template 3: sticky footer

页面内容不足一屏时，页脚贴着视口底部而不是"浮在中间"。要点：body { min-height: 100dvh; display: flex; flex-direction: column }，主体区 flex: 1。用 dvh 而不是 vh，因为移动端浏览器地址栏收起/展开时 vh 不会跟着变，会出现"底部被地址栏盖住"的经典问题。

When the page is shorter than the viewport, the footer sits at the bottom instead of floating in the middle. The key: body { min-height: 100dvh; display: flex; flex-direction: column } with the main area at flex: 1. Use dvh rather than vh, because on mobile browsers vh does not update as the address bar hides and shows, which produces the classic "footer hidden behind the address bar" bug.

模板 4：经典双栏（圣杯/双飞翼的现代写法）

Template 4: the classic two-column layout, modernised

过去用浮动 + 负边距实现，现在三行 flex 就够：侧栏 flex: none、主区 flex: 1; min-width: 0。窄屏时改成纵向堆叠（flex-direction: column 或换用 grid，见第 5 章）。

Once built with floats and negative margins, now three lines of flex: sidebar flex: none, main flex: 1; min-width: 0. On narrow screens it becomes a column (via flex-direction: column or by switching to grid — see Chapter 5).

破坏性测试清单（每个模板都该过一遍）：①文案换成英文/德语（词更长）；②标题里塞一个 30 字符的长单词；③放一张 2000px 宽的图片；④容器宽度压到 320px；⑤用户把字号放大到 200%。能同时通过这五项的模板才算可用——这也是 3.3 演示里那片"破坏按钮"存在的意义。

Stress-test checklist (run it on every template): (1) switch the copy to English or German (longer words); (2) put a 30-character word in the title; (3) add a 2000px-wide image; (4) squeeze the container to 320px; (5) zoom text to 200%. Only a template that survives all five is usable — which is what the "break it" buttons in the 3.3 demo are for.

🧩 案例诊断：问题 ⑤ 卡片高度不齐、图片撑破容器v1 的三张课程卡用 float: left; width: 32% 排布，问题有三个：①浮动元素高度不齐，卡片底部参差；②卡片内的"查看详情"按钮位置随文字长度上下浮动；③卡片里的课程封面图没有 max-width，一张 1200px 的图直接撑破卡片。改用 flex 之后：等高由 align-items 免费获得，按钮用 margin-block-start: auto 贴底，图片用 max-width: 100%; height: auto 收进容器。
🧩 Case diagnosis: defect ⑤ uneven cards and breaking imagesThe three v1 cards use float: left; width: 32%, which causes three problems: (1) floated items have unequal heights, so the card bottoms are ragged; (2) the "view details" button drifts up and down with the length of the text; (3) the course cover image has no max-width, so a 1200px image bursts the card open. With flex: equal heights come free from align-items, the button is pinned with margin-block-start: auto, and the image is contained by max-width: 100%; height: auto.

关键代码 ① 等高卡片 + 按钮贴底

Key code ① Equal-height cards with bottom-pinned buttons

一次写好，之后无论卡片里加多少字，版面都不会乱。

Write it once and the layout survives any amount of added copy.

.card-row {
  display: flex;
  gap: var(--space-6);
  /* align-items 默认就是 stretch，所以三张卡片自动等高 —— 不用写 */
}

.card {
  flex: 1 1 0;
  min-width: 0;                 /* ⭐ 防长内容撑破（见 3.2） */
  display: flex;
  flex-direction: column;       /* ⭐ 关键点 ①：卡片内部走纵向主轴 */
  gap: var(--space-3);
}

.card__body { flex: 1; }        /* ⭐ 关键点 ②：正文吃掉剩余高度 */
.card__cta  { margin-block-start: auto; }   /* 双保险：按钮永远贴底 */
.card__cover { max-width: 100%; height: auto; display: block; }  /* ⭐ 关键点 ③：图片不撑破容器 */
.card-row {
  display: flex;
  gap: var(--space-6);
  /* align-items defaults to stretch, so the three cards equalise automatically — no need to write it */
}

.card {
  flex: 1 1 0;
  min-width: 0;                 /* ⭐ prevents long content from blowing it open (see 3.2) */
  display: flex;
  flex-direction: column;       /* ⭐ Key point ①: the card lays out along a vertical main axis */
  gap: var(--space-3);
}

.card__body { flex: 1; }        /* ⭐ Key point ②: the body absorbs the leftover height */
.card__cta  { margin-block-start: auto; }   /* belt and braces: the button always sits at the bottom */
.card__cover { max-width: 100%; height: auto; display: block; }  /* ⭐ Key point ③: images cannot break out */

关键点解释：坑：如果卡片里放了 position: absolute 的装饰元素，它不会参与 flex 的高度计算，"等高"会在视觉上失效（卡片看着还是不等高）。另外 flex: 1 1 0 的 0 是 flex-basis，写成 flex: 1 时浏览器会自动补成 1 1 0%，两者等价；但显式写出来更适合教学与代码审查。

Key point: Pitfall: if a card contains an absolutely positioned decoration, that decoration takes no part in flex height computation and the "equal height" look breaks. Also note that in flex: 1 1 0 the 0 is flex-basis; flex: 1 expands to 1 1 0%, which is equivalent — but writing it explicitly reads better in reviews and teaching material.

关键代码 ② 页脚贴底：100dvh 而不是 100vh

Key code ② Sticky footer: 100dvh, not 100vh

内容不满一屏时页脚贴底；内容超过一屏时页脚自然跟随文档流。

The footer sticks to the bottom when the page is short, and follows the document normally when it is long.

body {
  /* ⭐ 关键点 ④：dvh = 动态视口高度，移动端地址栏收放时会同步更新 */
  min-height: 100dvh;
  display: flex;
  flex-direction: column;
  gap: 0;
}

.site-main { flex: 1; }        /* 主体吃掉剩余高度，把页脚压到底部 */
.site-footer { margin-block-start: auto; }   /* 或者在这里也用 auto margin */

/* 兼容旧浏览器时可以写成两行：
   min-height: 100vh;
   min-height: 100dvh;   后者覆盖前者，不支持的浏览器自动忽略 */
body {
  /* ⭐ Key point ④: dvh = dynamic viewport height, updated as mobile address bars show and hide */
  min-height: 100dvh;
  display: flex;
  flex-direction: column;
  gap: 0;
}

.site-main { flex: 1; }        /* the main area absorbs the leftover height and pushes the footer down */
.site-footer { margin-block-start: auto; }   /* or use an auto margin here instead */

/* For older browsers, write both lines:
   min-height: 100vh;
   min-height: 100dvh;   the second overrides the first; unsupporting browsers ignore it */

关键点解释：100vh 在 iOS Safari 上长期偏大（等于"地址栏收起时"的高度），所以内容底部会被地址栏盖住，用户得滚一下才能看到。视口单位家族现在的分工是：vh 大视口、svh 小视口、dvh 动态跟随、lvh 大视口。做"满屏"布局用 dvh；做"绝不溢出"的布局（比如全屏对话）用 svh 更安全。

Key point: On iOS Safari 100vh was long measured as the "address bar hidden" height, so content at the bottom sat behind the address bar until the user scrolled. The viewport-unit family now divides the work: vh large viewport, svh small viewport, dvh dynamic, lvh large. Use dvh for full-screen layouts; for layouts that must never overflow (a full-screen dialog, say), svh is the safer choice.
